# Development workflow

1. Define the observable behavior and integration boundary.
2. Implement cohesive modules of at most 500 physical lines per code/configuration file.
3. Verify behavior with isolated fixtures and meaningful regression tests.
4. Render changed UI at supported sizes using fictional data.
5. Review the diff, source archive, licenses and privacy before publication.
6. Submit a pull request; the maintainer reviews it before merging.

This document contains public development guidance, not personal session notes or a release promise.
